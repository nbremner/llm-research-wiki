System architecture · August 2026

How the research wiki runs itself

A public research wiki on AI workforce transformation × I-O psychology that finds its own literature, triages it, and drafts synthesis — with a hard rule about who gets to decide what becomes canon. The design splits every step by a single question: is this mechanics, or is this judgment?

The pipeline

1

Discover

Code Daily · 08:00

A Python harness queries OpenAlex, arXiv, and Crossref with ~30 seed queries derived from the wiki's own open questions, dedupes against a ledger of everything already seen, and ranks candidates against the wiki's concept vocabulary. No LLM anywhere in this step.

2

Acquire

Code

Each surfaced candidate walks an acquisition ladder until something works. What can't be fetched is flagged for manual pickup — never silently dropped.

open-access resolve → direct PDF → reader snapshot → agent browser (last resort)

3

Stage

Code

Candidates and their PDFs land in a visible Drive inbox with a machine-readable manifest. Every later decision is a folder move you can watch: pending → wiki / read-once / discarded.

4

Triage

Agent Code Daily · 08:30

The agent judges every candidate against an owner-calibrated rubric: wiki, read-once, or discard — and anything ambiguous stamps no decision at all; it stays pending and surfaces to the owner instead. A deterministic applier performs every file move, so the model never touches mechanics. The day's calls arrive as a Discord digest.

5

Synthesize

Agent Owner On demand

One source at a time. Evidence records — what a paper says, with public provenance — auto-commit, because they're low-judgment. Topic synthesis is drafted by the agent but becomes canon only when the owner approves the exact diff.

The wiki itself

Plain markdown in a git repository: a short public front door, four orientation map pages, 49 cross-linked topic pages of synthesis, and 75 source records. Contradictions are surfaced in prose, never auto-resolved — disagreement between studies carries meaning. Git history is the audit log; there is no database to drift out of sync.

6

Publish

Code Every 6 hours

A GitHub Action rebuilds the public site from the repo — only the wiki content ships; the machinery stays home.

Three loops keep it honest

Stage 4 ↩ its own rubric

Rubric friction

Ambiguous triage calls accumulate into a rolling 14-day friction report. When several share a cause, the agent may propose one rubric amendment per day — and that's all it can do. The owner ratifies by editing the rubric in git, prospectively; the agent never edits its own rules.

Wiki ↩ Stage 5 · Monthly

Semantic lint

A deterministic shortlist pairs topics that cite the same evidence — the mechanism by which contradictions creep in. The agent reads each pair and flags only wiki-voice contradictions, plus any topic whose sources are newer than its last synthesis. Findings are report-only: fixes go back through the owner-approved synthesis queue, and a finding clears itself the moment the wiki changes.

Wiki ↩ Stage 1 · Compounding

The flywheel

The wiki's open questions and research gaps seed tomorrow's discovery queries. The better the synthesis gets, the sharper the scan — the system hunts for exactly what it doesn't yet know.

Rules of the game

Determinism split

Code selects, collects, and moves; the model judges. Neither crosses over.

Owner-gated canon

Nothing becomes synthesis without a human-approved diff. One gate, always closed by default.

Report-only audits

Lint proposes and routes; it never rewrites. Findings clear when the wiki does.

Caps on every loop

Every scheduled job is volume-capped, deduped, and logged. No loop becomes a backlog sink.

One source of truth

Git holds machinery and content. Each fact lives in one place; everything else links to it.

Ambiguity surfaces

When the agent isn't sure, it doesn't guess — the record stays pending and a human decides.

Stack: Python + systemd timers on a small VPS · a Hermes-based agent for judgment · Google Drive for artifacts and staging · Discord for digests and approvals · GitHub Pages (Quartz) for the public site.
